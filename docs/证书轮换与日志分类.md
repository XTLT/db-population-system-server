# 证书轮换机制（路线B 第3项）

## 背景

- 服务器生产环境由 systemd 启动 gunicorn，证书路径**显式写死在服务配置**中：
  `--certfile /root/population-system/data/certs/server.crt`
  `--keyfile  /root/population-system/data/certs/server.key`
- 代码内 `config.CERT_DIR` 与 systemd 实际路径**可能不一致**（26 上二者不同），
  因此轮换必须以 systemd 实际路径为准，不能只依赖 `cert_manager.py`。
- 客户端（桌面端 v0.0.26+ / 移动端 v0.0.22+）已启用证书固定校验：
  - 桌面端：内置 `certs/server.crt`，`CERT_REQUIRED` 校验
  - 移动端：内置 `assets/certs/server.crt`，SHA-256 指纹钉扎（fail closed）
  **服务器换证书后，客户端必须同步重新打包，否则全部连接失败（这是防护预期行为）。**

## 轮换流程（标准操作）

1. 登录 26：`ssh root@192.168.9.26`
2. 执行轮换脚本（自动完成 备份→生成→重启→验证→回滚保护）：
   ```bash
   cd /root/population-system/server
   bash scripts/rotate_cert.sh
   ```
   脚本步骤：
   - 备份旧证书到 `data/certs/backup/server.{crt,key}.<时间戳>`
   - openssl 生成新自签证书（10 年，SAN 含 `localhost`、`tension02.ren`、`192.168.9.26`）
   - 重启 `population-server`，验证 active；失败自动回滚旧证书
   - 打印新证书有效期用于验收

3. 拷出新证书用于客户端打包：
   ```bash
   scp root@192.168.9.26:/root/population-system/data/certs/server.crt ./
   ```

4. **重新打包三端客户端**（内置新证书）：
   - 桌面端：替换 `desktop/certs/server.crt` → 版本号 +1 → 打包 → 双推双发
   - 移动端：替换 `mobile/assets/certs/server.crt` → 版本号 +1 → 打包 → 双推双发
   - 服务器端：本次改动随 git 双推即可

5. 发布后用户升级客户端；旧版本客户端会提示连接失败（证书校验不过）。

## 回滚

- 脚本内置回滚：服务未启动时自动恢复备份证书并重启。
- 手动回滚：
  ```bash
  cp -a /root/population-system/data/certs/backup/server.crt.<TS> /root/population-system/data/certs/server.crt
  cp -a /root/population-system/data/certs/backup/server.key.<TS> /root/population-system/data/certs/server.key
  systemctl restart population-server
  ```

## 验证新证书

```bash
echo | openssl s_client -connect 127.0.0.1:5000 -servername tension02.ren \
  2>/dev/null | openssl x509 -noout -subject -dates -ext subjectAltName
```

## 日志分类速查（路线B 第2项）

| 事件 | 位置 | 示例 |
|---|---|---|
| TLS 握手失败（客户端证书不受信等） | `data/logs/error.log`（gunicorn） | `[SSL: TLSV1_ALERT_UNKNOWN_CA] tlsv1 alert unknown ca` |
| 登录失败：用户名不存在 | `server/logs/app.log`（应用） | `[登录失败][用户名不存在] user=xxx ip=xxx` |
| 登录失败：密码错误 | `server/logs/app.log` | `[登录失败][密码错误] user=xxx ip=xxx 账号失败次数=N` |
| 登录失败：账户锁定 | `server/logs/app.log` | `[登录失败][账户锁定] user=xxx ip=xxx 剩余N分钟` |
| 登录失败：IP 封锁 | `server/logs/app.log` | `[登录失败][IP封锁] ip=xxx 剩余N分钟` |

注：应用日志路径以 `config.LOG_DIR` 解析为准（26 上为 `server/logs/app.log`）。
